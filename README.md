# RecentlyDivorced

Keeps top-level human CLI conversations recognizable. Preserves protected names.

```text
pending activity ─────────┐
stock / CompactVeteran     ├─► 1500-char capsule ─► 12-word label ─► /resume
young chat ───────────────┘
```

## install

```bash
curl -fsSL https://raw.githubusercontent.com/lmtlssss/RecentlyDivorced/main/install.sh | sh
```

inspect first:

```bash
curl -fsSLO https://raw.githubusercontent.com/lmtlssss/RecentlyDivorced/main/install.sh
less install.sh
sh install.sh
```

## usage

the source ladder is:

1. stock compaction summary, plus the latest user turn;
2. optional read-only GraphFather objective + Cursor + Next action;
3. young first ask + latest six semantic turns.

legacy and paginated top-level human CLI rows are covered. subagents, exec,
fork, and internal threads are excluded. local rollout reading stops at 64 KiB;
conversation evidence stops at 1500 characters.

the first pass batches with Sol at low reasoning. changed-only maintenance uses
Luna at low reasoning. one-line labels stay short.

Meaningful activity is queued locally on prompt submit. Labels refresh
asynchronously after a response, so typing never replaces a good title with a
raw prompt fragment.

To inspect labels without changing the cache or production thread titles, pass
one or more IDs to the read-only preview command:

```bash
recentlydivorced --preview THREAD_ID [THREAD_ID ...]
```

The preview combines the optional GraphFather context with recent conversation
evidence and returns JSON labels and capsules.

## Task context and name ownership

A generic opening such as `continue`, `/resume`, or `yes, thanks` is not a task.
RecentlyDivorced waits until the conversation or optional GraphFather context
identifies useful work. It uses the stored working-directory name as context,
not as evidence of the task. It does not scan the repository for naming.

Two sessions in `shop`, both opened with `continue`, can therefore become
`Shop checkout retries repair` and `Shop login expiry investigation` once their
normal work establishes those tasks. These are illustrative labels; generated
wording can vary. The current task takes priority over an older goal. Labels
retain the existing limit of 12 words and 120 characters.

A generic follow-up does not replace useful evidence. Unchanged evidence reuses
the stored result. A model can return an empty label when the task is uncertain;
that decision is reused until the evidence changes. No blank name is published.
The local fast path uses no model. Initial and changed evidence can still use
the configured Sol/Luna labeling requests.

Names already written by RecentlyDivorced remain eligible after upgrade. A
pre-existing name with unknown origin is protected. An observed external rename
also stops automatic updates. This applies even when the name could have been
created by Codex's own automatic title generator: the plugin cannot prove its
origin. To explicitly allow an existing thread to use automatic labels:

```bash
rd="${CODEX_HOME:-$HOME/.codex}/plugins/data/recentlydivorced-recentlydivorced/recentlydivorced"
"$rd" --auto THREAD_ID
```

The next normal refresh applies the policy. This does not rename other threads.
To keep the current name unchanged, including a label generated by the plugin:

```bash
"$rd" --pin THREAD_ID
```

Both commands accept multiple explicit IDs. Neither command starts a model.

Local title ownership and activity revisions reject delayed results after newer
observed input or a pin. A conditional SQLite update applies a generated name
only if the native stored name still matches the captured name. Cache reuse no
longer rewrites names or transcript previews. Uninstall restores only a label
that is still owned by the plugin; it preserves later external names.

**Native boundary:** this remains a Linux x86_64 plugin using Codex's local
`state_5.sqlite` store, not a native cross-platform Codex feature. Its conditional
write protects that database row. It cannot guarantee shared title ownership,
same-text manual-rename detection, or immediate agreement across the active TUI,
compatibility indexes, and other clients. Use `--pin` for an explicit local pin.
The native request in [openai/codex#14044](https://github.com/openai/codex/issues/14044)
remains necessary for one canonical writer and atomic origin/revision checks.

## build

```bash
cargo test --locked --manifest-path plugins/recentlydivorced/runtime/Cargo.toml
cargo build --locked --manifest-path plugins/recentlydivorced/runtime/Cargo.toml
python3 scripts/prove-labels.py
```

The lifecycle proof runs the actual binary against temporary Codex-shaped stores
and a deterministic model-process stub. It covers task discovery, two tasks in
one project, cache reuse, manual renames, in-flight changes, explicit ownership,
legacy-cache upgrade, uncertainty, and child isolation. It does not spend model
usage or change real conversation data. It is not a live-model quality benchmark
or proof of native TUI synchronization.
